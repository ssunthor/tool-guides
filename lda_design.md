## 1. Introduction & Purpose

The **Legal Document Assistant (LDA)** is the user-facing web application and API gateway for the broader Legal Knowledge Base (LKB) suite. Positioned as the interactive portal for Legal, Deal Desk, and Finance teams, it provides a modern, fast, and intuitive interface to explore, verify, and manage the lifecycle of AI-parsed legal contracts.

Acting as the "Interface" of the suite, the LDA decouples the user experience from the heavy backend processing of the Legal Document Parser (LDP). It reads directly from the shared PostgreSQL database to display real-time extraction results and provides a "Human-in-the-Loop" (HITL) validation interface. Furthermore, it acts as a remote control for the processing cluster, utilizing a dedicated gRPC connector to dispatch reprocess or cancellation commands directly to the LDP worker nodes.

## 2. Architecture & Core Components

The LDA is built using a modern decoupled architecture: a robust **FastAPI backend** serving a highly responsive **React Single Page Application (SPA)** built with Vite and Material UI (MUI).

### 2.1 Backend (FastAPI)
* **`rest_api/main.py`**: The application entry point. Configures CORS, custom logging middleware, serves the static React build, and mounts the API routers.
* **`rest_api/routers/documents.py`**: The core API endpoints. Handles listing documents, fetching detailed metadata, streaming source PDFs directly to the browser, and processing HITL `PUT` requests to update extracted fields.
* **`core/connectors/ldp_connector.py`**: The gRPC bridge. It establishes a secure channel to the Legal Document Parser's `ldp.proto` service (port 50061), allowing the API to trigger `ReprocessDocument` and `CancelDocument` RPCs.
* **`core/database/`**: Reuses the SQLAlchemy ORM `DocumentJob` models to natively query and manipulate the exact same database records the parser generates.
* **`rest_api/dependencies.py`**: Handles authentication and authorization by parsing injected `x_forwarded_*` headers from the enterprise API Gateway.

### 2.2 Frontend (React / Vite)
Structured using **Feature-Sliced Design (FSD)** principles, ensuring high maintainability:
* **`ui/src/pages/`**: The top-level route containers (`DashboardPage`, `DocumentExplorerPage`, `DocumentationPage`, `DocumentPage`).
* **`ui/src/features/`**: Domain-specific UI components grouped by feature.
    * **`dashboard/`**: Contains `StatCard` and the `ParsingPerformanceWidget` for visualizing cluster metrics (e.g., Avg Time per Page, Total Broken Tables Auto-Fixed).
    * **`explorer/`**: Contains the complex list views, filter bars (`DocumentFilterBar`), smart-grouping accordions (`DocumentGroupAccordion`), and confidence tooltips.
    * **`document/`**: Contains the core Split-Screen UI. `DocumentViewer` toggles between the original PDF stream and the rendered Markdown. `MetadataPanel` provides the editable forms for HITL validation.
* **State Management**: Utilizes `@tanstack/react-query` for smart-polling and caching, ensuring the UI remains perfectly synced with the database without manual refreshes.

## 3. User Workflows

### 3.1 Real-Time Dashboard & Monitoring
Upon login, users land on the Dashboard. It aggregates data from the `document_jobs` table to display live KPIs: Total Processed, Success/Failure rates, Active Queue size, and unique entity counts. The Parsing Performance Widget gives technical users insight into the health and speed of the backend LDP cluster.

### 3.2 Document Exploration & Smart Polling
The Document Explorer provides a densely packed, filterable view of all contracts.
* **Grouping:** Documents are automatically grouped by their resolved `cmd_client_group_name`.
* **Smart Polling:** If any document in the list is in a `pending` or `processing` state, React Query engages a 2-second polling interval. Users can watch the progress bar fill and read live status updates (e.g., *"OCRing page 4/12..."* or *"Repairing broken table on Page 88..."*) streamed directly from the LDP Celery workers.
* **Confidence Tooltips:** Instead of overwhelming the list view, granular AI confidence scores (derived from token logprobs) are hidden behind an intuitive tooltip on the global confidence badge.

### 3.3 The Split-Screen Validation (HITL)
Clicking a document opens the `DocumentPage` (or the `DocumentDebugDialog`).
* **Left Pane (Viewer):** Uses `react-pdf` to stream the original source document, or `react-markdown` to render the fully stitched, table-repaired Markdown output generated by the AI.
* **Right Pane (Metadata):** Displays the ~140 extracted fields. Users can review the AI's reasoning, verify the resolved CMD Client IDs, and ultimately change the `Review Status` from `unassigned` to `validated`. 
* **Remote Control:** If the OCR was poor or the LLM hallucinated, users can click "Reprocess" to instantly fire a gRPC command to the LDP cluster to wipe the stats and re-run the pipeline.

## 4. Key Technical Features

* **gRPC Remote Control:** The LDA is not just a passive reader; it actively commands the LDP cluster using Protobuf-defined RPCs to manage job states, bypassing the need for complex database state-machine hacks.
* **React Query Smart Polling:** Minimizes database load. The frontend only hammers the backend for updates when it inherently knows a background task is actively running.
* **Dynamic Markdown Rendering:** Utilizes `remark-gfm` and `rehype-raw` to safely render complex HTML tables natively inside the Markdown view, fully supporting the LDP's "Double-Rip" table repairs.
* **Unified Theme Context:** A custom MUI theme provider featuring a modern dark mode (`#050810` backgrounds with `#4ed869` primary accents) with a subtle grid-overlay background, switchable via a context toggle.

## 5. Configuration & Deployment

* **`config/settings.yaml`**: The single source of truth for the environment. Maps the API port (7892), database DSN, and the endpoint addresses for the external CMC (50053) and LDP (50061) gRPC servers.
* **`legal_document_assistant.py`**: The CLI launcher that bootstraps the virtual environment, configures Uvicorn, and starts the FastAPI server.
* **`deploy.sh`**: A shell script automating the Vite production build (`npm run build`) and the systemd service restart for seamless deployments.
* **`utils/logging_setup.py`**: Configures dual-channel logging (Console + Rotating Files) and actively filters out noisy API Gateway health checks (`/health`) from the access logs.

## 6. Future Enhancements

### 6.1 Chat & Semantic Retrieval Integration
**Objective:** Evolve the LDA from a metadata validator into a conversational RAG interface.
* **Implementation:** The UI will introduce a third pane (or replace the metadata panel contextually) with a Chat interface. The backend will integrate with the future **Legal Contract Retriever (LCR)** gRPC service to route natural language queries (e.g., *"What are the termination clauses across Vodafone contracts?"*) into Hybrid SQL/Vector searches, returning precise citations that auto-scroll the PDF viewer.

### 6.2 Dynamic Field Generation (Self-Service)
**Objective:** Allow business users to define new extraction fields without developer intervention.
* **Implementation:** Add a configuration UI allowing users to define a new prompt and data type. The LDA backend will insert this into the database and fire a broadcast command to the LDP cluster to retroactively run the new extraction against the cached Markdown of all previously processed documents.
